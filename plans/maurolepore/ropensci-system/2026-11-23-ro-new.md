# ro-new — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `tools/bin/ro-new <command-name>`, a generator that scaffolds a new `ro-*` command in `tools/bin/` as an executable bash script with an empty quoted heredoc.

**Architecture:** `ro-new` is a bash generator (it computes paths, so unlike the prompt scripts it cannot be a pure heredoc command). It resolves its own directory via `BASH_SOURCE`, validates the single argument, refuses to overwrite, writes the scaffold from a quoted outer heredoc, then sets the executable bit. See [Personal ops tooling](../../../concepts/personal-ops-tooling.md) for where the generated command fits.

**Tech Stack:** bash, `grep`, `chmod`; no dependencies.

**Spec:** none — this plan is itself the design, approved in conversation on 2026-11-23.

## Global Constraints

- Generated filename is always `ro-<command-name>`; the prefix is added by the generator.
- Generated command matches the `ro-pattern-*`/`ro-checklist-*` shape: `#!/usr/bin/env bash` plus `cat <<'RO_TEMPLATE_EOF' ... RO_TEMPLATE_EOF`, left empty for the author to fill.
- Inner and outer heredoc delimiters must differ (`RO_NEW_EOF` vs `RO_TEMPLATE_EOF`).
- Generator must work from any cwd; usage errors go to stderr.

## Review Focus

- A name like `../evil` must not write outside `tools/bin/`.
- An existing `ro-foo` must not be clobbered.
- Running from a foreign cwd must still write into the repo's `tools/bin/`.
- A name with spaces, slash, or leading hyphen must be rejected.
- The generated heredoc must be literally preserved (no expansion).
